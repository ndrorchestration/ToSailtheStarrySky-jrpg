## Root-cause defect and correction

The first 1280×720 SceneCapture2D output contained only background. The first 1920×1080 automation screenshot likewise showed sky. Actual live UE geometry diagnostics found the authored three-quarter camera pointed away from the ship: forward/target dot product **0.11685**. The benchmark authored `look_at_rotation` as `(pitch,yaw,roll)`, but Python's positional `unreal.Rotator(...)` constructor interprets parameters `(roll,pitch,yaw)`. The review source now constructs with `unreal.Rotator(angles[2], angles[0], angles[1])`; a source regression asserts that order. For the existing *saved old map*, the automation review corrected CineCamera rotation **only in memory** using UE's `MathLibrary.find_look_at_rotation`, measured the corrected alignment as **1.0**, and never saved temporary camera edits. The original map remains for independent review. New maps built with the corrected source get the right rotation at creation.

Actual UE 5.8 Interchange also puts imported StaticMeshes under a nested `.../StaticMeshes/...` subfolder, not the old flat review asset path. The binder now allowlists only the exact known wing/support nested review objects, retaining strict noncanonical provenance; tests reject alternate folders and traversal. The native UE enum string `<AureateWakeForm.SKYBORNE: 0>` is handled through its `.name` property rather than a fragile endswith test. `capture_first_wake_review` defers optional `AutomationScheduler` validation until scheduling, preserving source-only capture preflight.
